## 1. The Plan (What was intended)

This session was the **first full implementation pass of the River Vector device-side codebase** for the River Song integration. Going in, the repo had:
- A bootstrap-style `units/voyager.json` with hardware specs hardcoded
- A working `api_client.py` for talking to River Song over plain HTTP
- Existing hardware/safety/autonomy modules built against `UnitProfile` from a static JSON
- No claim flow, no command stream, no telemetry batching, no per-unit config pull

The plan was to:

1. **Write the full integration spec** as the contract for both sides of the integration (River Vector device + River Song server, with Antigravity implementing the latter).
2. **Refactor River Vector to be a universal program**: hardware comes from server, not from a checked-in JSON. Any future mower (Kepler, robot, push-mower) runs the same codebase with different per-unit config.
3. **Implement the device side of the spec** (spec §13, all 16 sub-items).
4. **Generate an Antigravity handoff prompt** so the Google CLI agent could implement the River Song side without re-deriving the spec.
5. **Produce a hardware CAD mock-up** of the Voyager electronics enclosure so the layout (2× Pi + Pico + fans + cannon plug + external antenna) could be validated before parts orders.
6. **Lock the hardware operational model**: external switch → auto-boot via systemd → phone → zone select → mow.

### Device-side foundations (committed `e7359b1`)

- **`core/constants.py`** — stripped per-unit values; kept only universal constants (absolute safety floors, filesystem paths, long-poll timing, FaultCode + ConnectivityTier enums). Legacy constants retained with deprecation markers for callers that haven't migrated.
- **`core/bootstrap.py`** (new) — load/save `/etc/river-vector/bootstrap.json` with atomic writes, `WifiNetwork` dataclass, device-bound XOR-encrypted PSK storage via keystore.
- **`core/identity.py`** (new) — first-boot `unit_id` generation from RPi serial + random suffix, 6-digit claim code generation, full `UNCLAIMED → CLAIMING → CLAIMED` state machine with `secrets.compare_digest` for constant-time verification.
- **`connectivity/wifi_manager.py`** (new) — joins networks from bootstrap in priority order via `wpa_supplicant`; sim-mode on non-Pi development machines.
- **`connectivity/connectivity_probe.py`** (new) — probes server URLs (primary internet, LAN fallback), reports tier (`internet`|`lan`|`offline`|`meshtastic_only`), captive portal detection.
- **`connectivity/api_client.py`** (refactor) — switched to `X-Unit-Token` header auth, probe-based URL selection, batched telemetry, session start/end, command ack/complete, teach waypoint push.

### Device-side connectivity (committed `ac361bc`)

- **`connectivity/config_sync.py`** (new) — pulls full config bundle from `GET /api/vector/config/{unit_id}`, validates schema, caches to `/var/lib/river-vector/config_cache.json`. Defensively clamps safety floors to absolute device-side bounds on every receipt (server can't push unsafe values). Exposes `HardwareCapabilities` dataclass.
- **`connectivity/command_stream.py`** (new) — long-poll loop with sub-100ms command latency, immediate ack-on-receipt, `X-Config-Version` change detection, exponential backoff on errors, auth-failure callback for re-claim transition.
- **`connectivity/telemetry_thread.py`** (new) — state-driven cadence push (1s in FAULT/ESTOP, 5s in AUTO, 30s in IDLE), 500-entry offline ring buffer, batch replay up to 50/call when reconnected.
- **`connectivity/mdns_advertise.py`** (new) — zeroconf broadcast on `_rivervector._tcp.local.` during CLAIMING; graceful degrade if zeroconf not installed.
- **`connectivity/claim_server.py`** (new) — `http.server` listener on port 8765 for the claim handshake; receives `{claim_code, unit_token}` from River Song, verifies code, persists token via `Identity.complete_claim`.

### Device-side autonomy + boot integration (committed `dc15849`)

- **`core/main.py`** (refactor) — full new boot sequence: bootstrap → identity → WiFi (pre-agreed SSIDs) → NTP sync → connectivity probe → claim flow (if unclaimed) → register → config pull → hardware build → telemetry/command threads → IDLE → main loop. Command dispatcher routes `mow_start`, `mow_stop`, `return_home`, `estop`, `estop_reset`, `manual.*`, `teach.*`, `config.refresh`. Auth failure auto-resets claim state. Legacy config shims (`_PathPlannerShim`, `_MowSessionShim`, `_ReturnHomeShim`) adapt the new dict-based config to old attribute-style consumers.
- **`core/hardware_factory.py`** (refactor) — reads hardware config from `config_sync.get_hardware()` dict instead of static `UnitProfile`. Components gated by `HardwareCapabilities`; missing hardware degrades to sim mode (e.g., `cameras.count == 0` → permanent sim `CameraManager`).
- **`safety/interlocks.py`** (refactor) — reads safety floors from `config_sync.get_safety_floors()` at `verify()` time. Adds tilt cutoff check (uses configured cutoff degrees) and `supports_autonomous` capability gate (refuses AUTO on units without RTK GPS + IMU). Skips fuel/GPS checks when sensor not declared in config.
- **`autonomy/mode_manager.py`** (extend) — `OperatingMode` enum grown to all 12 states per spec §2 (`UNCLAIMED`, `CLAIMING`, `SETUP_PENDING`, `IDLE`, `MANUAL`, `AUTO`, `RETURNING_HOME`, `ESTOP`, `FAULT`, `OFFLINE_REPLAY`, `TEACH`, `SHUTDOWN`). Added `set_mode()` for lifecycle transitions that bypass interlock pre-flight.
- **`autonomy/manual_control.py`** (new) — handles `manual.drive` / `manual.steer` / `manual.brake` / `manual.blades` with 1-second watchdog auto-stop; blade engagement requires operator presence.
- **`autonomy/teach_mode.py`** (new) — boundary teach mode: 1Hz GPS waypoint capture, 5s push interval, finalize-on-end commits zone to River Song.
- **`scripts/install.sh`** (new, +x) — provisioning script: `install` (creates dirs + service user + systemd unit), `uninstall`, `reset` (back to UNCLAIMED), `add-wifi <ssid> <pw>` (encrypts PSK), `status`.
- **`units/example.json`** (new) — bootstrap template for fresh devices.
- **`README.md`** (rewrite) — universal-program architecture, provisioning steps, 12 operating states, bootstrap format, connectivity hierarchy.

## 4. Errors & Bugs Fixed

### Session-opening fix (commit `da41550`)

- **Symptom**: `RegisterBody` had a field named `model_config`. Pydantic v2 reserves `model_config` as the model's own config attribute; it silently dropped the field on the wire.
- **Root cause**: Field named after a Pydantic-reserved attribute.
- **Files**: `connectivity/api_client.py`, `core/main.py`
- **Fix**: Renamed field to `unit_config`; added `dataclasses.asdict(profile)` in `_build_config_shim()` so the full `UnitProfile` blob serializes cleanly into the register payload. Verified via `python -c "import dataclasses; ... json.dumps(...)"` — produces the exact `voyager.json` structure.

### Test infrastructure fixes during dev

- **Symptom**: `test_identity.py` failed on dev machines (Chromebook Crostini) because `Identity.begin_claiming()` writes to `/var/lib/river-vector/claim_code.txt`, which doesn't exist outside production.
- **Root cause**: Tests didn't mock the claim_code file write path.
- **File**: `tests/test_identity.py`
- **Fix**: Added `@patch` decorators on `core.identity.write_claim_code` and `clear_claim_code` so tests don't touch `/var/lib`.

- **Symptom**: `test_command_stream.py::test_config_version_callback` failed asserting last-call value, but the fake session returned multiple responses with different `X-Config-Version` headers.
- **Root cause**: Mock recorded last call, not first-with-specific-arg.
- **File**: `tests/test_command_stream.py`
- **Fix**: Use `unittest.mock.call(42) in on_version.call_args_list` rather than `assert_called_with(42)`.

## 5. Errors & Bugs Created / Regressions Introduced

Two design choices worth flagging as **intentional tech debt**:

1. **Legacy constant aliases in `core/constants.py`** — Voyager-specific numeric defaults retained under a "Legacy constants" comment block with deprecation notes. This is not a regression — it's a deliberate bridge so the migration to per-unit config doesn't require touching every hardware driver in one commit. They will be removed as each consumer migrates.

2. **`_PathPlannerShim` / `_MowSessionShim` / `_ReturnHomeShim` in `core/main.py`** — config adapter shims wrapping the new dict-based config into the old attribute-style object that these three autonomy modules expect. Same rationale as #1. Removable once the three modules are refactored to consume `config_sync.get_config()` natively. Not a bug; not unsafe; just transitional.
